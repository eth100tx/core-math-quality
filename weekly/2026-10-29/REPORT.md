## Three useful improvements

1. **Correct the proof's algorithm and sign statements.** LargePath assigns `f_h <- S_h`, while the code and error analysis use `C_h`. The identity `cos((-1)^t x)=cos(z+y)` loses the half-turn sign; use `cos(x)=(-1)^t cos(z+y)`. The moderate proof also needs an exact signed reduction rather than equality merely modulo pi. AccurateLarge's prose says to add in the first-quadrant/positive-residual case, although the algorithm and C correctly subtract; later prose reverses another case and retains `sin` in a cosine formula. The near-zero argument has `3/2` where the relevant quarter turn is `3/4`. A [proposed proof patch](../../candidates/cos-proof-errata/README.md) makes these corrections. These are proof-document defects, not demonstrated implementation bugs.
2. **Make the small-input and census evidence precise.** The accurate-reduction lemma still states `x>=2^-16`, although cosine calls it down to `2^-27`. The exponent sentence also confuses `e` with the table index `i`. We supply the extension argument, exact table/index checks and 11,286 sampled MPFR comparisons. The cited `0x1.6ac5b262ca1ffp+850` has cosine near **-1**, not near zero. In the 17,222-row added section, 16,778 rows have `|cos(x)|<2^-27`; the other 444 do not meet that threshold (412 have magnitude near one). The smallest measured boundary distance in the small-cosine subset occurs at **`0x1.6477e472c5074p+715`**, approximately **`2^-120.3902083648`**. The original example's `2^-120.7758358723` distance is numerically correct but belongs to the near-one class. This checks the supplied data; it does **not** regenerate the exhaustive completeness census.
3. **Document the exception fallback instead of calling coverage complete.** GCC/gcov's four-mode union is **171/172 lines, 43/44 arcs**. The missing line is `exceptions:761` (`return ret`); the missing arc is `[exceptions,759,1]`, the false exit from the fourth comparison. No valid public-entry witness was found, and no unreachability proof is claimed. All four listed exceptions hit the actual unsigned guard and match MPFR in all four modes. The paper's guard includes low limb `2^64-1`; C actually accepts only `[2^64-5,2^64-2]` and falls back for an unlisted input. The proposed patch aligns that description with C; excluding additional inputs needing correction, including low limb `2^64-1`, remains a hard-case completeness premise. A direct call to the helper would not count as a coverage witness through `cr_cos`.
